# Code Generation Tools Policy

## Scope

This policy applies to all employees, contractors, and third-party users who use code generation tools, including tools that offer AI-assisted code completion, generation, or modification in any development environment across the organization.

## AI use in software testing

- Only AI tools approved for use may be used. This includes approved corporate AI tools and tools approved through the standard technology radar governance process.
- Documents classified as Official may be used with AI tools. Documents with a classification higher than Official must not be used with AI tools.
- AI tools must not be used to process personal information for software testing.
- Users must not use data that could cause harm to the organization, including access tokens or other secrets.
- If in doubt about AI use in software testing, seek guidance from the Lead Test Engineers.

## Data security and confidentiality

- Users must ensure that adopted tools do not inadvertently share sensitive, classified, or personally identifiable information (PII) with external services during code generation.
- Interactions with adopted code generation tools should comply with the organization's encryption and data residency policies, so that transmitted data is handled securely.
- Use of adopted tools must align with internal and external information security requirements, including those applicable to cloud-hosted environments.

## Intellectual property and licensing

- The UK Hydrographic Office retains ownership of the codebase. Users must understand how generated code is integrated to ensure that third-party intellectual property rights are not inadvertently compromised.
- Outputs produced by code generation tools should be verified for licensing compliance. Generated code must not introduce code snippets that conflict with the organization's licensing policies.
- Only vetted and appropriately licensed tooling should be used for UKHO codebases.
- Generated code should be treated as a draft and fully reviewed before integration to ensure alignment with the organization's intellectual property and licensing standards.

## Legal and regulatory compliance

- Use of code generation tools must comply with relevant local, national, and international regulations, including data protection laws such as GDPR and government-specific compliance requirements.
- Tools and processes should track and log the use of code generation technologies so that activities can be audited for legal and regulatory compliance.

## Code quality and review

- Code generated by these tools must undergo the same review, testing, and quality assurance processes as manually written code.
- Developers should integrate generated output into the existing codebase only after thorough review and necessary modifications.
- Feedback on generated code should be documented to improve tool usage and integration practices.

## Training and best practices

- Training programs should be provided for relevant roles, including software engineers (junior to principal), DevOps, and Data Engineers. Training should cover effective use of these tools and adherence to this policy.
- Documentation and guidelines for best practices should be maintained and updated regularly. Users should be encouraged to share feedback and lessons learned.
- Updates and refresher sessions should keep users informed about changes in the tools, best practices, and policy updates.

## Operational integration and monitoring

- Adopted tools should be evaluated for effective integration with the existing technology stack, workflows, and cloud environments.
- Monitoring of tool use should be available to identify deviations or potential misuse.
- Appropriate usage limits and access controls must be available for scenarios involving particularly sensitive or critical code.

## Risk management and accountability

- Risks associated with code generation tools, including the potential introduction of vulnerabilities or unlicensed code, should be assessed regularly.
- This policy and associated practices should be reviewed periodically to reflect evolving technology, regulatory changes, and emerging best practices.
- A feedback loop should enable users to report problematic outputs or suggest improvements. This information should be used to refine tool usage guidelines and this policy.
- Each user is responsible for ensuring that generated code complies with this policy and does not compromise the organization's security or quality standards.
