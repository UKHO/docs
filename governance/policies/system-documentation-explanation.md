# Why System Documentation Matters

This document explains the context for the [System Documentation Policy](system-documentation.md). The policy remains the authoritative source for requirements.

## Audience and purpose

System documentation is for the delivery team. Its purpose is to support future maintenance and provide a 'jump start into the code'.

## Just enough documentation

The Agile principle of "Working software over comprehensive documentation" should be followed. Documentation is required, but should be limited to what is needed to capture the elements in the policy.

## Code comments and user-focused documentation

The policy does not mandate code commenting standards. The guidance is that code should be comprehensible without comments, because comments are a maintenance overhead and can indicate poor code.

Teams should consider additional user-focused documentation, such as Javadoc or ///, if a package is to be consumed without the source code.
