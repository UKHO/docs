# Why We Publish UKHO Code Openly

UKHO's default is to make new source code open, in line with [GOV.UK Service Standard point 12](https://www.gov.uk/service-manual/service-standard/point-12-make-new-source-code-open), the [MOD Defence Service Manual, Section 12](https://www.digital.mod.uk/policy-rules-standards-and-guidance/service-manual/meet-the-standard), and [GDS guidance](https://www.gov.uk/government/publications/open-source-guidance/when-code-should-be-open-or-closed). Reusing and contributing to common components is preferred to re-inventing them.

Open code supports reuse, reduces duplication, and promotes transparency and cost-efficiency across government. Planning for openness from the start also avoids the later work of sanitising a repository before publication.

Openness can support security: publishing security-enforcing code, including cryptographic or authentication logic, can strengthen scrutiny. That does not remove the need to keep credentials separate or to withhold code that falls within a recognised exception. For Defence, this includes code directly relating to SECRET or TOP SECRET systems or content.

See the [Open Source Publishing Policy](open-source-publishing.md) for the authoritative requirements and the [how-to](open-source-publishing-how-to.md) for publication steps.
