# Inclusive Language Policy

## Applicability

This policy applies to anyone contributing to UKHO code or documentation in public or private repositories.

## Policy

All new documentation and code should be inclusive and facilitate diversity. Contributing authors are strongly encouraged to use neutral terms and avoid exclusionary language.

When working in an existing codebase, teams should be alert to opportunities to update the language used in documentation and code.

Documentation and code should avoid language that is discriminatory, condescending or may represent age bias, culture bias, disability bias, ethnic slurs, gender bias, gender-specific language, racial bias or sexual orientation bias.

Terminology that is normalized at a technical level but loaded at a societal level should be avoided when unnecessary to describe technical concepts. Examples include:

- master/slave
- blacklist/whitelist
- sanity check
- dummy

For new projects, a link to this policy should be provided from the `CONTRIBUTING.md` file. For existing projects, a link should be provided from the `CONTRIBUTING.md` file when the language in the code or documentation is updated.

For guidance on applying this policy and checking code and documentation, see the [inclusive language how-to](inclusive-language-how-to.md). For context and rationale, see the [inclusive language explanation](inclusive-language-explanation.md).
